# Changelog — Telegram Tag Distribution Manager (TG Tag Manager PRO)

## [1.3.2] - 2026-10-01
### Added
- Неблокуючі плаваючі сповіщення (Toast notifications) при копіюванні тегів замість системного `alert()`.
- Візуальний інтерактивний зворотний зв'язок на кнопці «Copy to Clipboard» (`#btnCopyTags`): тимчасова зміна тексту на `✓ Скопійовано!` та зеленого підсвічування.
- Валідація наявності вибраних тегів перед копіюванням.

## [1.3.1] - 2026-10-01
### Added
- Редизайн кнопок керування до естетики Outline/Ghost:
  - Суцільна акцентна кнопка для `Process IDs` (`#btnProcess`).
  - Контурні напівпрозорі кнопки дій (`#btnImport`, `#btnExport`, `#btnEdit`, `#btnReset`) з плавним заповненням кольором при ховері.
- Реактивний менеджер станів `updateButtonStates()`:
  - Автоматичне пульсуюче підсвічування кнопки `Import Base` (`.btn-pulse-needed`), коли база даних порожня.
  - Блокування кнопок `Export Base`, `Edit Base`, `Reset All` (`disabled`) при відсутності записів у базі.
  - Автоматичне розблокування при імпорті чи збереженні бази.

## [1.3.0] - 2026-10-01
### Added
- Фільтрація статусів (Усі / Активні / Звільнені) у модальному вікні редагування бази `Edit Base`:
  - Кнопки-перемикачі `Усі`, `Активні`, `Звільнені` у панелі інструментів.
  - Кольорові бейджі статусу (`status-badge active` / `status-badge dismissed`) у кожному рядку.
  - Адаптивна мобільна сітка для колонок редактора та статусу.
- Оновлено експорт у Excel (`employees_report.xlsx`):
  - Багатосторінковий файл (3 вкладки: `Усі співробітники`, `Активні`, `Звільнені`).
  - Чітка структура колонок: `ID`, `Ім'я`, `Telegram Handle`, `Статус` із заданою шириною колонок.

## [1.2.9] - 2026-10-01
### Added
- Функціонал клієнтського експорту бази операторів в Excel (`exportDbToExcel`):
  - Кнопка «Export Base (Excel)» у головному блоці керування.
  - Кнопка «Export Excel» у підвалі модального вікна редагування бази.
  - Автоматичне сортування за числовим ID та форматування заголовків `№ оп`, `Ім'я`, `Telegram`.
  - Динамічне найменування файлу з поточною датою (`Теги_операторів_YYYY-MM-DD.xlsx`).
- Безшовна ініціалізація початкового набору операторів з локального бекапу `opsDB_backup.json` при першому запуску (порожньому `localStorage`).

### Security
- Політика Zero-Leak: `DEFAULT_DB = {}` залишається строго порожнім у репозиторії.
- Файл `opsDB_backup.json` надійно ігнорується у `.gitignore`.
- Strict Push Policy: всі коміти залишаються строго локальними.

## [1.2.8] - 2026-10-01
### Fixed & Sanitized
- Автоматична санітизація імен операторів у `loadDB()`: шаблони `Оп {id}`, `Оп #{id}` або `#{id}` очищаються в порожній рядок `""`.
- Модальне вікно `Edit Base` показує чисте поле введення, якщо реальне ім'я відсутнє, запобігаючи збереженню технічних назв у `localStorage`.
- Рендеринг карток адаптовано:
  - З реальним ім'ям: `[✓] Оп ${id} — ${name}`
  - Без імені: `[✓] Оп ${id}` (підпис: `${tag}`).
- Покращено адаптивну поведінку `.card-title` та `.card-name` при довгих іменах.

### Security
- Політика Zero-Leak: `DEFAULT_DB = {}` залишається порожнім.
- Strict Push Policy: всі коміти залишаються строго локальними до явного тригера "пуш" / "push".
